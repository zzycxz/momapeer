# momapeer AI 自主浏览 + 应用内浏览器面板 — 实现方案 (v2)

## 背景与已定决策

为 momapeer 补强「AI 自主浏览」能力（给目标 → AI 看页面自己决策、端到端完成网页任务），并在应用内提供 ZCode 式的实时浏览器面板让用户看见 AI 操作。

**已确认的方向（多轮调研得出）：**
1. **Python + browser-use 作为 sidecar**（AI 自主浏览的标杆生态都在 Python；体积可接受）
2. **复用系统 Chrome/Edge，不打包 Chromium**（调研结论：ZCode/OpenWork 都不额外装浏览器；Windows Edge 自带满足「不让用户装环境」；省 200M）
3. **应用内实时面板**（CDP `Page.startScreencast` 帧流 → 前端 canvas/img 绘制）
4. **借鉴 ZCode 协议设计 + OpenWork CDP 工程实现**（合成两者优点）
5. **发行：安装包分发**；**平台：Windows 优先**（与现有 ppt-auto Windows-only Python 运行时一致）

**调研推翻的旧判断：**「Wails 做不了内嵌浏览器面板」是错的——CDP screencast 是非 Electron agent UI 的标准做法，且 momapeer 已有 ~80% 基础设施（CDP 会话池、AttachmentDataURL 图片管线、experts:collab 事件流模板、可调整面板布局）。

## 合成架构（借鉴 ZCode 协议 + OpenWork CDP）

```
Go 宿主 (momapeer.exe, Wails)
 ├─ 端口分配: net.Listen("127.0.0.1:0") 拿 OS 分配空闲端口 (改进版 OpenWork, 避免 TOCTOU)
 ├─ 浏览器探测: 现有 browserdetect.go (Chrome→Edge→Brave→Chromium)
 ├─ 拉起系统 Chrome: --remote-debugging-port=<port> --remote-debugging-address=127.0.0.1
 │                  --user-data-dir=<临时profile> --window-size=1280,900 等
 │                  + 启动完整性检查 (解析 Chrome 日志断言端口匹配, 借鉴 OpenWork)
 ├─ 三路竞速就绪探测 (轮询 /json/list 每250ms/20s超时 + 进程存活 + 进程退出检查)
 ├─ CDP screencast 订阅 (Page.startScreencast → frame 事件 → emit "browser:view:frame")
 │
 ├─ browser_auto(goal) 工具
 │    │  经控制通道把 ws://127.0.0.1:<port> 传给 sidecar (返回值握手, 不写文件, 借鉴 OpenWork)
 │    ▼
 │  Python sidecar (browser-use)
 │    ├─ connect_over_cdp(wsURL)  ← 复用 Go 拉起的系统 Chrome, 不自己 spawn
 │    ├─ agentic loop: domSnapshot→LLM→定位器→动作 (借鉴 ZCode 工作流纪律)
 │    ├─ 截图 base64 PNG 内联, "采集"与"提交模型"分离 (借鉴 ZCode)
 │    └─ 安全: URL 白名单 + evaluate 只读 + 会话隔离 (借鉴 ZCode)
 │
 └─ 前端 (React/Wails)
      └─ BrowserViewPanel.tsx 订阅 "browser:view:frame" → canvas/img 实时绘制
         挂在 cowork activePanel (与 experts/rag 同级)
```

**关键工程决策（综合两标杆）：**
- 端口由 Go 宿主分配（非 sidecar），避免 TOCTOU（改进 OpenWork 的固定列表探测）
- CDP URL 通过控制通道传 sidecar，不写文件轮询（OpenWork 返回值握手）
- Python sidecar 用 `connect_over_cdp` 连 Go 拉起的浏览器——这是「复用系统 Chrome」核心
- screencast 帧经 Wails 事件总线推送，复用 `experts:collab` 模式

## 交付分两阶段（风险递进）

### 阶段 1 — 原型验证（先做，风险最低）
用**开发环境 Python + browser-use**（非打包）跑通：sidecar 服务 + `browser_auto` 工具 + screencast 面板。**验证自主浏览质量和面板效果达标后**再打包。避免打包做完发现效果不行浪费投入。

### 阶段 2 — 打包进安装包（阶段 1 达标后）
内嵌 Python runtime + browser-use 依赖（镜像现有 ppt-auto 的打包链路）。

## 阶段 1 详细实现

### 1.1 Python sidecar 服务（新增）
**新文件 `desktop/browseruse_server.py`**：基于 stdlib `http.server` 的本地 HTTP 服务（127.0.0.1），镜像 `hyper_extract_server.py` 形态。
- `GET /health` → `{"ok": true, "browser_use_available": bool}`
- `POST /run` → 接收 `{goal, url?, max_steps?, cdp_url, model?, base_url?, proxy?}`，用 browser-use `Agent` 跑 agentic loop（`connect_over_cdp(cdp_url)` 连 Go 拉起的浏览器），**SSE 流**回传每步事件（思考/动作/截图/结果）
- `POST /stop` → 取消当前 run

**LLM 配置**：sidecar 从环境变量读密钥（Go spawn 时继承 `os.Environ()`，含 `OPENAI_API_KEY`/`ANTHROPIC_API_KEY` 等，宿主 boot 时 `loadDotEnv` 已注入，与 HE 服务器同模式）；model/base_url 由宿主 `POST /run` 传入。

### 1.2 Go 宿主：sidecar 服务管理（克隆 he_service.go）
**新文件 `desktop/browseruse_service.go`**：镜像 `he_service.go`，`BrowserUseService` 结构体（`mu`/`cmd`/`client`/`port`/`python`/`script`/`running`/`buAvail`/`cancelFn`）：
- `Start()`：端口探测 → `exec.CommandContext(ctx, python, script, --port, --host)` → `proc.HideWindow` → stdout/stderr 接管 → **不设 cmd.Env → 继承宿主环境含密钥** → `waitForReady()`（轮询 /health）→ `monitor()`
- `Stop()`：cancel + `Process.Kill()`（同 HE）
- `IsReady()`：`running && buAvail`
- `ResolveScript()`：clone `FindScript()` 找 `browseruse_server.py`
- Python 路径：阶段 1 用系统 python（`python`/`python3`）

### 1.3 Go 宿主：HTTP 客户端 + 事件流
**新文件 `internal/browseruse/client.go`**：类型化 Go 客户端（镜像 `internal/rag/he_client.go`）：
- `Health(ctx) (ok, buAvail bool, err)`
- `RunStream(ctx, req RunRequest) (<-chan Event, error)`：发 `POST /run`，逐行读 SSE 解析为 Event channel（`thought`/`action`/`screenshot`/`done`/`error`）
- `Stop(ctx)`

### 1.4 浏览器拉起 + CDP 端口管理（新增 Go 包）
**新文件 `internal/browserlaunch/launch.go`**：负责拉起系统 Chrome 并暴露 CDP URL（借鉴 OpenWork CDP 工程）：
- `Launch(ctx, opts LaunchOptions) (*Handle, error)`：
  - `net.Listen("tcp", "127.0.0.1:0")` 预分配端口（**OS 分配，避免 TOCTOU**）
  - 探测系统浏览器（复用 `browserdetect.go` 的 `detectBrowserPath`）
  - `exec.CommandContext` 启动，flags：`--remote-debugging-port=<port>` `--remote-debugging-address=127.0.0.1`（**必显式，防 0.0.0.0**）`--user-data-dir=<临时>` `--window-size=1280,900` `--no-first-run` `--no-default-browser-check` `--disable-popup-blocking`
  - **启动完整性检查**：读 Chrome stderr/`DevToolsActivePort` 文件，断言端口与预期一致（借鉴 OpenWork `daytona.ts:415-425`），不一致拒绝
  - **三路竞速就绪探测**：轮询 `GET /json/list`（250ms/20s）vs 进程退出 vs 进程不存活（借鉴 `local.ts:210-237`）
  - **SIGTRAP 重试**：有头 Chrome 偶尔 pre-CDP 带退出码退出，捕获后 `--headless=new` 重试一次（`local.ts:459-465`）
- `Handle` 持有 `wsURL`、`cmd`、取消函数；`Close()` 做 SIGINT→宽限→Kill 优雅关闭 + 端口释放
- 返回 `wsURL` 给 `browser_auto` 工具

### 1.5 新工具 `browser_auto`（复用现有工具模式）
**新文件 `internal/tool/builtin/browserauto.go`**：struct `browserAuto{}` + 四方法（`Name()`="browser_auto" / `Description()` / `Schema()` 参数 `{goal, url?, max_steps?}` / `ReadOnly()`=false / `Execute(ctx, args)`）。
- `Execute`：解析 args → 调 `browserlaunch.Launch` 拉起浏览器拿 wsURL → 调 sidecar client 的 `RunStream` → 事件流拼文本返回 Agent
- 句柄注入：加包级 setter `SetBrowserUseRunner(runner)`（仿 `SetBrowserLaunchOptions`），由 `boot.go` 注入 sidecar client + 浏览器拉起器
- **注册**：`browser.go` 的 `BrowserTools()`（约 58-75）末尾加 `browserAuto{}` → 自动经 `boot.go:509-513` 注册+Hide，**无需改 boot.go 注册逻辑**
- **接入 skill**：`"browser_auto"` 加入 `browser-auto` skill 的 `AllowedTools`（`builtins.go:460`）

### 1.6 应用内浏览器面板（CDP screencast → 前端实时绘制）
**核心机制**：CDP `Page.startScreencast` 把浏览器画面以 base64 帧流推送，前端实时绘制。复用现有事件总线（`experts:collab` 模板）和图片管线（`AttachmentDataURL`）。

**后端**：
- `internal/browserlaunch/screencast.go`：给 `Handle` 加 `StartScreencast(emit func(frame))`：`page.StartScreencast`（format=jpeg, quality=70, 限 maxWidth/maxHeight）+ `chromedp.ListenTarget` 监听 `page.EventScreencastFrame` → base64 解码 → `page.ScreencastFrameAck` → 调 emit 回调
- `desktop/browser_view_app.go`：`emitBrowserFrame(ev)` → `runtime.EventsEmit(a.ctx, "browser:view:frame", ev)`（镜像 `emitExpertsCollab` `experts_app.go:205-213`）；加 App 方法 `StartBrowserView`/`StopBrowserView` 绑定给前端
- 生命周期：`browser_auto` 执行期间自动开启 screencast；`closeBrowserSession` 时停（`browser.go:487-500`）

**前端**：
- `desktop/frontend/src/lib/bridge.ts`：加 `onBrowserFrame(cb)`（仿 `onExpertsCollab` `bridge.ts:687-689`）
- **新组件 `desktop/frontend/src/components/cowork/BrowserViewPanel.tsx`**：订阅 `onBrowserFrame`，最新帧存 state，用 `<canvas>`（`drawImage`）或 `<img src={dataUrl}>` 绘制；可叠加 AI 最近一次点击坐标（`browser_click` 已捕获坐标）
- **挂载点**：`CoWorkLayout.tsx` 加 `"browser"` 到 `activePanel` 状态机（与 `experts`/`rag`/`calendarTask` 同级，`:207-242`）；侧边栏加入口（仿 `CoWorkLayout.tsx:195-201` 知识库按钮）；用 `display:none` 切换保持挂载（仿 `:235-237` ExpertPanel 模式，避免切走丢流）
- 复用现有 dock 宽度/调整/切换机制（`App.tsx:687-688`）

### 1.7 桌面应用生命周期接入
**改 `desktop/app.go`**：仿 `app.go:484-499`（HE 接入）——desktop init 里 `NewBrowserUseService(...)` + `Start()`（失败**非致命**，`a.buService=nil`+告警）；shutdown 处 `a.buService.Stop()`（仿 `app.go:891-892`）。boot.go 注入 sidecar 句柄给 builtin 包。

### 1.8 配置项
**改 `internal/config/config.go` 的 `CoworkConfig`（约 470-483）+ `momapeer.example.toml`**：
- `browser_use_enabled bool`（默认 true）
- `browser_use_python string`（Python 路径覆盖；阶段1 系统 python，阶段2 打包 runtime）
- `browser_use_port int`（默认 18901，避开 HE 的 18900）
- `browser_headless bool`（已有，复用——screencast 时可选 headless 让真实窗口不抢焦点）

### 1.9 阶段 1 出口标准
- sidecar `/health` 正常
- `browser_auto {"goal":"打开 example.com 并截图"}` 端到端跑通
- 应用内面板能实时看到 AI 操作浏览器（screencast 流畅、延迟可接受）
- 至少 3 个真实站点任务（登录、搜索、表单填写）效果达标
- Stop/取消能中断运行

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| browser-use 自主浏览质量不达标 | **阶段1先原型验证**，达标再打包 |
| screencast 帧率/延迟不理想 | 调 quality/format/maxFrameDelay；worst case 退回截图轮询（现有 `browserScreenshot`）|
| Python `._pth` 硬编码致重定位失败 | 阶段2 明确修正为相对路径 |
| sidecar 崩溃拖垮主程序 | 隔离：失败非致命（`buService=nil`+告警），独立重启 |
| 两套浏览器（chromedp vs browser-use）状态不一致 | 明确分工：`browser_auto`=自主浏览用 sidecar；其余 `browser_*`=确定性操作用 chromedp |
| screencast 与真实 Chrome 窗口重复显示 | 配置 `browser_headless=true` 时真实窗口不显示，只 screencast 到面板 |
| CDP 端口无认证被本机其他进程劫持 | 绑定 127.0.0.1（必做）；后续可加令牌（ZCode broker 模式）|

## 不做的事（明确边界）
- 不重写现有 chromedp 工具（保留做确定性操作）
- 不打包 Chromium（复用系统 Chrome/Edge）
- 不做跨平台打包（Windows 优先）
- 不自建 Python↔Go 复杂 RPC（HTTP+SSE，与 HE 一致）
- 不做新的密钥管理（继承 os.Environ）
- 不迁移到 Electron（Wails + screencast 即可达成 ZCode 式面板体验）
