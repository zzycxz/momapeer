# 日历与任务功能全面升级方案

## 总览：4 大主题 + 1 个底层修复

经探索确认 1 个**阻断性底层 bug**：`SetEmailConfig` 全仓库无调用者，`globalEmailConfig` 永远 nil → **所有出站邮件功能当前完全失效**（email_send 工具、定时任务邮件投递都是死的）。这个必须最先修，否则后面邮件相关改造全部空转。

按依赖顺序分 5 个阶段：

---

## 阶段 1：修复邮件功能死代码（P0，阻断项）

**问题**：boot.go 只调 `SetEmailAccounts`，从不调 `SetEmailConfig`。`SendPlainText`（email.go:44）和 `email_send` 工具 Execute（email.go:196）都读永远为 nil 的 `globalEmailConfig`。

**改动**：
- `internal/tool/builtin/email.go`：
  - `SendPlainText(to, subject, body)` 改为走 `accountByName("")`（取 Default 账户），不再依赖 `globalEmailConfig`
  - 新增 `SendPlainTextAs(account, to, subject, body)`（按账户名发，供 scheduler/calendar 复用）
  - `email_send` 工具 Execute 改用 `accountByName(p.Account)`，并在 schema 加 `account` 字段（与 email_read/email_search 对齐）
  - 保留 `globalEmailConfig`/`SetEmailConfig` 但标记 deprecated，消除破坏性（避免动太多调用面）
- 新增测试验证多账户发送路径

  - `CoWorkSettingsView` 加 `EmailAccounts []EmailAccountView` 字段（保留 smtp/imap 单对象做向后兼容镜像）

  - `SetCoWorkSettings` 改造：当传入 `EmailAccounts` 非空时全量覆盖 `c.Cowork.EmailAccounts`，每账户 PasswordEnv 用 `COWORK_SMTP_PASSWORD_<name>` 避免互相覆盖，删除账户时清理 secret store 旧密钥
  - `ProbeMailAccount(name string)` 加参数，按名探测
- `desktop/frontend/src/lib/types.ts`：新增 `EmailAccountView` 接口
- `desktop/frontend/src/lib/bridge.ts`：`ProbeMailAccount` 签名加 name 参数；mock seed 补 accounts
- `desktop/frontend/src/components/SettingsPanel.tsx`：邮箱区从"2 个输入框"重做为"账户列表卡片"（每条：name/smtp host+port+encryption+from+username+密码、imap host+port+username+密码、设为默认、删除、+新建账户、每条独立探测状态点）

## 验证策略

2. `go vet ./internal/...` 受影响包
3. `go test ./internal/scheduler/ ./internal/calendar/ ./internal/bot/` 回归测试
4. scheduler/calendar 加新单测覆盖：多账户发送、deliverOutput 失败反馈、Event 迁移幂等、reminder 多通道 fan-out
5. `cd desktop/frontend && npx tsc --noEmit` 前端类型检查
6. CSS 检查（注：仓库预存一处 rag-dock 花括号错误，非本次引入，会标注）

## 风险与缓解

- **SQLite 迁移**：用 PRAGMA 检测+条件 ALTER，幂等可重复执行；老库新库都覆盖
- **EmailSender 接口签名变更**：是破坏性改动，但 EmailSender 只在 scheduler 包内和 desktop 桥接用，调用面可控
- **多账户 PasswordEnv**：每账户独立 env 名，删除账户时清理 secret，避免泄漏
- **dest 格式兼容**：两段格式（`feishu:oc_xxx`）必须保持工作，三段（`qq:group:xxx`）是新增能力

## 不在本次范围（避免膨胀）

- 微信/QQ 获取群名 API（受平台限制，成本高，本次靠 UserName 兜底）
- 一次性任务"启动补跑"选项、日历 timezone 真正生效（评估报告 P3 项，单独迭代）
- ICS 导入导出携带 output 字段（5b 标注可选）
